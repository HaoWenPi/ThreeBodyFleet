## 一、素材实况（先说清楚，避免误解）

| 项目 | 实际情况 |
|---|---|
| 提供的 STL | `Natural Selection-Full.stl`，3,019,184 B，二进制，**60,382 三角面**；包围盒 X 0–38.15 / Y 0–85.92 / Z 0–176.04 mm |
| STL 自带属性 | attr byte 全为 0 → **无顶点色**；格式本身**无 UV、无材质、无贴图、无节点层级** |
| 同目录素材 | `Natural Selection(3).stl` 与 Full 逐字节相同；5 个打印拆件 STL；`obj_1…3mf`（BambuStudio 工程，XML 内无 material / color / texture 定义） |
| 提供的图片 | 5 张 RGBA 抠图设计图（多角度渲染），**不是 UV 贴图** |
| 独立贴图文件 | **0 个**（整个素材目录无任何 .mtl / 贴图 / PBR atlas） |
| 上次提供的 GLB | `NatureSelectionStartship.glb` 86.3 MB，内含 3 张 4096 PBR 贴图 |

所以「完整绑定所提供的全部贴图」是这样落实的，**没有虚构**：

1. **5 张设计图全部登记并绑定**到具体部位/视角，无遗漏、无重复 → `bindings.json → designRefBindings`
2. 上次 GLB 里的 **3 张原始 PBR 贴图逐字节提取保留**，作为可追溯细节源 → `textures/source/`
3. 以两者为依据**重建**一套可渲染的分区 PBR 贴图集（4 张 2048² atlas），逐部位一一绑定
4. 没有把设计图伪装成 UV 贴图，也没有声称 GLB 贴图被直接投射到 STL（拓扑不同、STL 无 UV，做不到，强行投射必然错位）

> 如果你手上另有正式 UV/PBR 贴图，给我路径即可按同一 manifest 增量替换槽位，几何和绑定结构都不用动。

## 三、结构化模型表示

**坐标变换**：STL 打印系（X = 厚度 / Y = 圆环直径 / Z = 长轴，舰首在 +Z）→ Three.js Y-up：

```
Three(x, y, z) = (STL_y, STL_x, -STL_z)，原点取包围盒中心，缩放 76 / 176.04
```

行列式 +1，是纯旋转、不镜像；舰首落在 −Z、舰尾落在 +Z≈+38，与现有场景的尾焰挂点 `Z_END = 38.0` 天然兼容。

**面级分区**（按下列优先级判定，每个三角面恰好归入一个部位，合计 60,382 面，无遗漏无重叠）：

| 优先级 | 规则 | 归入部位 |
|---|---|---|
| 1 | 独立连通分量（≠最大主船体，2 个对称件） | `engine_pods` |
| 2 | z < 20 | `aft_booms` |
| 3 | z > 145 | `nose_cone` |
| 4 | z > 112 | `forward_hull` |
| 5 | z > 100 | `waist` |
| 6 | \|y−43\| > 37 且 28 < z < 100 | `radiator_fins` |
| 7 | r = hypot(z−65, y−43) > 33 | `ring_outer` |
| 8 | r > 17 | `ring_frame` |
| 9 | x > 26（上表面） | `bridge_deck` |
| 10 | 其余 | `hub_core` |

**三种读取方式**：读结构 → `manifest.json`；读几何/编辑 → `ship-structured.glb`（节点名 `部位ID / 中文名`）；网页直接加载 → `ship-structured.js`。

## 七、绑定正确性校验

```
python tools/validate_bindings.py     → RESULT PASS  checks=22 failed=0   退出码 0
```

校验读的是**真实产物**而不是 manifest 自述：解析 GLB 的 accessor 取 `TEXCOORD_0` 实际数组、逐 mesh 检查 UV 是否留在自己的槽位；检查 10 材质是否各用一次、三角面总数是否等于 60,382、4 张 PNG 是否真为 2048²、5 张设计图文件是否存在且 sha256 匹配。

不变量：① 每个三角面恰好属于一个部位 ② 每部位独占一个槽位、无两部位共槽 ③ 所有 UV 落在自身槽位内 ④ 5 张设计图全部绑定且 ID 唯一 ⑤ 每部位至少被一张设计图覆盖。

**反向验证**（证明断言不是恒真）：复制一份包，把 `summary.missing` 改成 1、把槽 0 的 UV 区域改窄 → 校验准确报出 2 项 FAIL（`binding summary declares 0/0/0`、`every real UV stays in its own slot`），退出码 1。

## 八、后续怎么读取 / 编辑 / 展示

- **换贴图**：只替换 `textures/atlas_*.png` 中对应槽位的像素（保持 512×512 范围），几何与绑定都不用动
- **改分区 / 配色**：改 `tools/build_structured_ship.py` 的 `classify()` 规则或 `PARTS` 表，重跑：
  `python tools/build_structured_ship.py --stl <STL> --refs <设计图目录> --glb <源GLB> --out <输出目录> --length 76 --atlas 2048`
- **结构化编辑**：`ship-structured.glb` 用 Blender 打开，10 个节点各自可分离、改材质、重导出
- **效果展示**：打开 `preview-structured.html`（`?mode=textured|grey|ids&view=0..4&part=-1..9`）
- **游戏默认舰体**：直接打开即是结构化 STL 版；地址加 `?hull=glb` 回到上一代 GLB 对照（`?hull=structured` 仍兼容）
- **加载兜底**：结构化载荷缺失时自动补载 GLB，再退到程序化舰体，HUD 会如实显示数据来源

## 九、局限（如实说明）

1. STL 无 UV，采用**按面主导轴的盒式投影**生成 UV。相邻面主导轴不同处会有图案接缝，复杂曲面上图案会有拉伸/重复。这里保证的是「绑定关系无缺失、无错位、无重复」，不等于「纹理图案在曲面上零重复」。
2. 4 张 atlas 是依据参考图配色与图案**程序化重建**的涂装，不是原模型的官方贴图。
3. 上次 GLB 的 3 张 4096 PBR 贴图**逐字节保留但未投射**到 STL（拓扑与 UV 不兼容，强行投射会产生错位，与「对应准确」的要求冲突）。
4. 游戏场景**默认旗舰已替换**为结构化 STL 版（2026-11-05 更新）；`?hull=glb` 可回到上一代 GLB 对照。首次打开需多下载约 9 MB 内联载荷。
5. 5 张设计图是透明抠图渲染图，只能作为配色与部位设计依据，不能直接当 UV 贴图贴用。
6. 实际帧率未实测（无头环境测不了 FPS）；结构化版 6.04 万面 / 4 张 2048 贴图，开销低于现有 15 万面版本。
